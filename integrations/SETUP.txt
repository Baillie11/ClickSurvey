Puzzle Path
- Source/client: Puzzle Path. Event: hunt_completed. Survey: puzzle-path-feedback.
- WordPress plugin: puzzlepath-clicksurvey/puzzlepath-clicksurvey.php, version 1.0.0.
- The queue reads paid bookings joined to pp_booking_progress completed records.
  Only completions at/after 2026-10-24 08:24:14 UTC qualify. Existing booking and
  quest code is unchanged. WordPress table prefixes are resolved at runtime.
- Durable outbox, stable booking event ID, 30-day per-email cap, invalid-email
  exclusion, retry backoff, maximum eight failed deliveries, no historical backfill.
- VentraIP collector authenticates to the WordPress REST events/ack endpoints
  with the dedicated Puzzle Path bearer key. Those endpoints expose only queued
  survey payloads and their acknowledgements. Anonymous access is denied.
- The collector posts each unchanged event to ClickSurvey /clicksurvey/api/events,
  then acknowledges the WordPress queue. Lost acknowledgements safely replay the
  same ID/payload. HTTPS certificate checks remain enabled; redirects are rejected.
- GET collection and POST acknowledgement send no-cache headers. Disabling the
  WordPress connection blocks collection as well as new completion scans.
- This direction is intentional: OrangeHost 209.172.2.80 times out opening TCP443
  to VentraIP 43.250.142.26. DNS was correct and VentraIP's firewall checker reported
  the IP unblocked. VentraIP-to-WordPress HTTPS works, so no host security was disabled.
- Private job: /home/clickeco/.config/clicksurvey/puzzlepath-survey-job.sh
  Collector: same directory/collect-puzzlepath.cjs; cron every minute with flock.
  Logs: same directory/puzzlepath-survey.log (aggregate counts/errors, no payloads).
- Settings -> ClickSurvey contains enable switch, queue counts, scan and test buttons.
  Test button queues only the administrator-selected test recipient for collection.

Pause and recover
- Puzzle Path: disable Automatic requests in WordPress Settings -> ClickSurvey.
  To pause only the collector, remove its exact cron entry after saving crontab.
- VitaePro: set CLICKSURVEY_ENABLED=false in .env (worker reads each run), or disable
  first_cover_letter. Restart the web service if changing flags displayed by it.
- ClickSurvey: disable the site's API client to reject new submissions, or have
  the operator set its automation rule Inactive in the database. The current
  Automation UI creates rules but does not edit existing ones. Accepted delivery jobs
  remain queued; disabling a rule is not cancellation of already accepted mail.
- After fixing a failed source queue, review its payload and ClickSurvey event
  status before resetting that specific row to pending/next_attempt UTC now.
  Preserve its event ID/payload so retries cannot duplicate invitations.
- Key rotation: create a replacement client with the exact same source name and
  only that site's survey ID; save the replacement key in both the source and
  private collection state where applicable, test it, then disable the old client.
  Do not simply replace the key in one location for Puzzle Path.
- Keep source database backups: the WordPress/VitaePro outboxes carry delivery
  state and caps; ClickSurvey's database backup does not include those databases.
- Existing minute jobs append logs. Include these small logs in regular disk-usage
  review and rotate/archive them as needed. They contain no keys or customer email.
