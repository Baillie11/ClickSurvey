ClickSurvey remediation record — 17 October 2026

Implemented
- Closed public registration; default bootstrap password removed. Administrators
  are explicitly provisioned using admin:create. Existing prototype users receive
  no automatic admin rights. This is one trusted admin team, not tenant hosting.
- Persistent MySQL sessions, login session rotation, required session secret,
  secure production cookies, CSRF form protection, request limits and headers.
- Express 5 catches async handler rejections; API errors hide server details.
- Indexed random API key identifiers, cryptographic secrets, scoped source names
  and allowed survey IDs. Legacy keys are disabled by migration.
- Required stable event IDs with a per-client unique database constraint,
  canonical payload fingerprints, duplicate detection and conflict responses.
- Transactions use checked-out connections and insert result IDs. Deadlocks are
  retried only around database work. Partial survey response writes roll back.
- Durable scheduled invitation queue, separate worker, bounded SMTP retries,
  SMTP TLS settings, escaped HTML, delivery status API, admin delivery monitor,
  Failed resend action, worker heartbeat and readiness endpoint.
- Ambiguous SMTP outcomes become DeliveryUnknown for manual provider review;
  interrupted Sending records are not blindly resent. SMTP acceptance and a
  database update cannot be atomic; no exactly-once email claim is made.
- Private invitations require a sent/opened, unexpired, unsuppressed invitation
  and an Active survey; transactional completion and unique completion keys
  prevent duplicate private responses. Required answers, types, choices, ranges
  and lengths are checked on the server. Public surveys intentionally permit
  multiple independent responses.
- Working unsubscribe confirmation endpoint and global suppression. Email scanner
  GET requests cannot unsubscribe recipients. No unsupported 'reply STOP' claim.
- Survey/question configuration validation, soft archival of questions preserving
  historical answers, safe CSV output and updated in-app API documentation.
- Versioned repeatable migration, separate setup/runtime database privileges,
  explicit InnoDB baseline and persistent session/worker tables.
- Updated dependencies: npm audit reports zero known vulnerabilities.
- Runnable server-side Node client and WordPress plugin client with timeout and
  response/error handling; caller-side business hooks/retry storage remain the
  responsibility of the originating website.
- Database dump helper, ignored backup directory, restore/retention runbook and
  real isolated backup restoration test. No recurring automation was scheduled.
